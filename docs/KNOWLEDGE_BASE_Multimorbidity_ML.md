## หมวดที่ 1: แก่นคิดทางระบาดวิทยาและระบบสุขภาพ

### 1.1 Multimorbidity คืออะไร และต่างจาก Comorbidity อย่างไร?
* **Comorbidity (โรคร่วม):** คือสภาวะที่มี "โรคหลัก 1 โรค (Index Condition)" เช่น ผู้ป่วยได้รับการวินิจฉัยว่าเป็นมะเร็งลำไส้ แล้วศึกษาว่ามีโรคเบาหวานหรือความดันโลหิตสูงเป็นโรคร่วมอยู่ด้วยหรือไม่ จุดโฟกัสอยู่ที่ผลกระทบต่อโรคหลัก
* **Multimorbidity (พหุก่อโรค):** คือสภาวะที่บุคคลมี **"โรคเรื้อรังตั้งแต่ 2 โรคขึ้นไปร่วมกัน"** โดยไม่ได้มองว่าโรคใดสำคัญกว่าโรคใด ทุกโรคมีศักดิ์ศรีเท่าเทียมกัน และส่งผลกระทบต่อสุขภาพ องค์รวม กิจวัตรประจำวัน และการใช้ยาของผู้ป่วย
* **ทำไมต้องตัดเกณฑ์ที่ $\ge 2$ โรค?**
  * ทางการแพทย์และระบาดวิทยาพบว่า เมื่อผู้ป่วยก้าวข้ามจาก 1 โรค ไปเป็น 2 โรค ความเสี่ยงต่อการนอนโรงพยาบาล อัตราการเสียชีวิต และค่ารักษาพยาบาลจะไม่ได้เพิ่มขึ้นแบบบวกทีละนิด แต่จะ **พุ่งขึ้นแบบทวีคูณ (Exponential Jump)**

### 1.2 "หน้าต่างโอกาส (Golden Window)" ของผู้มีโรคเรื้อรัง 1 โรค
* **กลุ่มที่มี 0 โรค:** เป็นกลุ่มเป้าหมายของ Primary Prevention (ป้องกันไม่ให้เกิดโรคเลย) ดูแลด้วยการส่งเสริมสุขภาพทั่วไป
* **กลุ่มที่มี $\ge 2$ โรคแล้ว:** เป็นกลุ่มที่โรคลุกลามแล้ว การดูแลจะซับซ้อนมาก ต้องคอยตามแก้ปัญหาเรื่องยาตีกันและภาวะแทรกซ้อน
* **กลุ่มที่มี "1 โรคพอดี" (Single Chronic Disease):** นี่คือ **"หน้าต่างโอกาสที่ดีที่สุด (Golden Window)"** ของระบบสุขภาพ เพราะ:
  1. คนกลุ่มนี้เข้ามาอยู่ในระบบบริการสุขภาพแล้ว (ต้องมารับยาและตรวจติดตามที่ รพ.สต./รพช. สม่ำเสมอ)
  2. ร่างกายเพิ่งเริ่มมีความผิดปกติ ยังไม่เกิดพหุก่อโรคเต็มขั้น
  3. หากเรามีเครื่องมือบอกได้ล่วงหน้าว่า "ในบรรดาคนที่มี 1 โรค ใครกำลังจะเกิดโรคที่ 2" ทีมสุขภาพจะสามารถเข้าไปแทรกแซง ปรับพฤติกรรม และควบคุมโรคได้อย่างมีประสิทธิภาพสูงสุด คุ้มค่างบประมาณที่สุด

### 1.3 ปัญหา Polypharmacy (ภาวะการใช้ยาหลายขนาน)
* **นิยาม:** การได้รับยาตั้งแต่ **5 ชนิดขึ้นไปต่อวัน**
* **สถานการณ์ในไทย:**
  * ผู้สูงอายุที่มีหลายโรคในระดับปฐมภูมิของไทย ได้รับยา $\ge 5$ ชนิดสูงถึง **36.8%**
  * กว่า **61%** ของกลุ่มนี้มีปัญหา **การกินยาไม่สม่ำเสมอ (Non-adherence)**
  * ส่งผลให้เกิดอันตรกิริยาระหว่างยา (Drug-Drug Interactions), ตับและไตเสื่อมจากยา, ภาวะความดันตกเมื่อเปลี่ยนท่า และการหกล้มในผู้สูงอายุ

## หมวดที่ 2: แก่นคิดด้าน Machine Learning

### 2.1 ทำไมต้องใช้ Machine Learning? ทำไมไม่ใช้คะแนนความเสี่ยง (Risk Score) แบบเดิม?
* **แบบจำลองเดิม (Traditional Linear Score):** คำนวณแบบเส้นตรงและแยกส่วน เช่น อายุเพิ่ม 1 ปี บวกความเสี่ยง 2%, สูบบุหรี่บวก 5 คะแนน
* **ความจริงในร่างกายมนุษย์ (Non-linear & Multidimensional):** ร่างกายผู้สูงอายุมีความซับซ้อนสูงมาก เช่น "คนอ้วนแต่มีกิจกรรมทางกายสูง" อาจเสี่ยงน้อยกว่า "คนผอมแต่ไม่ขยับร่างกายเลยและมีความดันสูง" ปฏิสัมพันธ์ข้ามมิติเหล่านี้ (Interaction terms) สถิติเชิงเส้นธรรมดาตรวจจับได้ยาก แต่ **Tree-based Machine Learning** สามารถเรียนรู้รูปแบบที่ไม่เป็นเส้นตรงเหล่านี้ได้อย่างแม่นยำ
* **หลักการคิดเชิงวิทยาศาสตร์:** เราไม่ได้ตั้งเป้าว่า ML ต้องชนะเสมอ แต่เราสร้างโมเดลเพื่อ **"ทดสอบและพิสูจน์"** ว่า ML ให้คุณค่าเพิ่มเหนือกว่าแบบจำลองพื้นฐานอย่างแท้จริงหรือไม่

### 2.2 อัลกอริทึมแต่ละตัวที่ใช้ ทำหน้าที่อะไร?
1. **Simple Logistic Regression (Baseline Model):**
   * ใช้เพียง 2 ตัวแปร: **อายุ + ชนิดของโรคเดิม**
   * หน้าที่: เป็น "มาตรวัดมาตรฐาน (Benchmark)" ที่ง่ายที่สุด เพื่อตอบคำถามว่าโมเดล ML ที่ซับซ้อนกว่านั้นคุ้มค่าที่จะนำมาใช้หรือไม่
2. **ElasticNet (Penalized Logistic Regression):**
   * คือ Logistic Regression ที่เพิ่มระบบลงโทษ (Penalty: L1 Lasso + L2 Ridge) เพื่อตัดตัวแปรที่ไม่จำเป็นออกและป้องกันปัญหา Overfitting
3. **Random Forest Classifier:**
   * ใช้หลักการ Bagging สร้างต้นไม้ตัดสินใจ (Decision Trees) นับร้อยต้นขึ้นมาอย่างอิสระ แล้วนำผลการทำนายมาโหวตเสียงข้างมาก ช่วยลดความแปรปรวน (Variance)
4. **XGBoost & LightGBM (Gradient Boosted Decision Trees):**
   * อัลกอริทึมแชมป์สำหรับข้อมูลแบบตาราง (Tabular Data)
   * ใช้หลักการ Boosting คือสร้างต้นไม้ต้นแรกขึ้นมา แล้วสร้างต้นไม้ต้นถัดไปเพื่อ **"เน้นแก้ข้อผิดพลาด (Residuals)"** ของต้นไม้ต้นก่อนหน้า ทำซ้ำไปเรื่อย ๆ ทำให้มีความแม่นยำสูงมาก

## หมวดที่ 3: 4 หลุมพรางทางสถิติที่อาจารย์ชอบถาม

### 3.1 Competing Risk of Death (การเสียชีวิตก่อนเกิดโรค)
* **ปัญหา:** ในการติดตามผู้สูงอายุ 3 ปี จะมีผู้สูงอายุจำนวนหนึ่ง **"เสียชีวิตไปก่อน"** ที่จะเกิดโรคที่ 2
  * *ถ้าตัดคนกลุ่มนี้ทิ้ง:* จะเกิด Selection Bias (เหลือแต่คนแข็งแรงที่มีชีวิตรอด)
  * *ถ้านับคนตายเป็น 0 (ไม่เกิดโรค):* จะทำให้โมเดลคิดว่าคนกลุ่มนี้สุขภาพดีจนไม่เกิดโรค ซึ่งผิดความเป็นจริง
* **ทางออกที่ถูกต้อง:** ต้องวิเคราะห์แบบ **Cause-specific Hazard** (ดูความเสี่ยงในกลุ่มที่ยังมีชีวิต) ร่วมกับการรายงาน **Cumulative Incidence Function (CIF)** แบบ Fine-Gray เพื่อประเมินความเสี่ยงสะสมจริงโดยไม่บิดเบือน

### 3.2 Detection Bias (อคติจากการตรวจพบ)
* **ปัญหา:** ผู้สูงอายุที่อาศัยในเขตเมือง หรือผู้ที่เข้าออกโรงพยาบาลบ่อย ๆ ย่อมมีโอกาสได้รับการตรวจเลือดและพบโรคที่ 2 สูงกว่าผู้สูงอายุในชนบทที่นาน ๆ ไปหาหมอที (ไม่ใช่เพราะคนเมืองป่วยจริงมากกว่า แต่เป็นเพราะ **ถูกตรวจพบมากกว่า**)
* **ทางออกที่ถูกต้อง:** พัฒนาและเปรียบเทียบโมเดล 2 ชุด คือ **ชุดที่มี** และ **ชุดที่ไม่มี** ตัวแปรการใช้บริการสุขภาพ/เขตพื้นที่ เพื่อยืนยันว่าความแม่นยำของโมเดลไม่ได้มาจากการพึ่งพาความถี่ในการเข้าโรงพยาบาล

### 3.3 Data Leakage (ข้อมูลรั่วไหล)
* **ปัญหา:** หากทำ Data Imputation (เติมค่าว่าง) หรือ Normalization บนข้อมูลทั้งหมดก่อนแบ่ง Train/Test ข้อมูลสถิติของ Test Set จะรั่วเข้าไปยัง Train Set ทันที ทำให้โมเดลดูเหมือนแม่นยำสูงเกินจริง
* **ทางออกที่ถูกต้อง:** ต้องใช้ **Nested Cross-Validation** เท่านั้น โดยทุกขั้นตอนการเตรียมข้อมูลต้องเกิดขึ้นภายใน Fold การฝึก (Training Fold) เท่านั้น

### 3.4 Class Imbalance (ทำไมงานนี้ถึงห้ามใช้ SMOTE?)
* **ปัญหา:** สัดส่วนคนที่ไม่เกิดโรค (Class 0) มักมีมากกว่าคนที่เกิดโรค (Class 1)
* **ข้อควรระวัง:** งาน Data Science ทั่วไปมักใช้ SMOTE (สร้างข้อมูลสังเคราะห์) แต่ในงานประเมินความเสี่ยงทางการแพทย์ **ห้ามใช้ SMOTE** เพราะจะทำลายสัดส่วนความชุกจริง (Prevalence) ในประชากร ส่งผลให้ค่าความน่าจะเป็นที่โมเดลคำนวณได้ (% Probability) ผิดเพี้ยนอย่างรุนแรง
* **ทางออกที่ถูกต้อง:** ใช้เทคนิค **Cost-sensitive Learning (Class Weight Balancing)** ปรับค่าน้ำหนักความสำคัญในสมการ Loss Function แทน

## หมวดที่ 4: การประเมินผลโมเดลทางการแพทย์

### 4.1 Discrimination vs Calibration (ความต่างที่สำคัญที่สุด)
* **Discrimination (การแยกแยะ):** วัดด้วย **ROC-AUC** และ **PR-AUC**
  * คือความสามารถในการบอกว่า "ในคนไข้ 2 คน คนที่เสี่ยงสูงกว่า อยู่ในกลุ่มเกิดโรคจริงหรือไม่" (เป็นการจัดลำดับ Rank Order)
* **Calibration (ความตรงของความน่าจะเป็น):** วัดด้วย **Calibration Slope** (เป้าหมาย = 1.0) และ **Brier Score**
  * คือความสอดคล้องระหว่าง "ตัวเลขความน่าจะเป็นที่โมเดลบอก" กับ "อัตราการเกิดโรคจริง"
  * *ตัวอย่าง:* ถ้าโมเดลทำนายว่าคนไข้มีความเสี่ยง 20% หมายความว่าในคนที่มีลักษณะแบบนี้ 100 คน จะต้องป่วยจริงประมาณ 20 คน
  * **คำเตือนสำคัญ:** ต่อให้โมเดลมีค่า AUC สูงถึง 0.85 แต่ถ้า Calibration แย่ (โมเดลบอกเสี่ยง 80% แต่จริง ๆ มีคนเป็นแค่ 10%) แพทย์จะไม่สามารถนำตัวเลขนี้ไปใช้ตัดสินใจทางคลินิกได้เลย เพราะจะทำให้เกิดการรักษาเกินจำเป็น (Overtreatment)

### 4.2 Decision Curve Analysis (DCA) และ Net Benefit
* เป็นวิธีประเมิน **คุณค่าสุทธิทางคลินิก (Clinical Utility)**
* ตอบคำถามแพทย์และผู้บริหารว่า: หากนำโมเดลนี้ไปใช้คัดกรองผู้ป่วยที่จุดตัดความเสี่ยงต่าง ๆ (เช่น ตัดที่ความเสี่ยง $\ge 20\%$) จะให้คุณค่าสุทธิ (Net Benefit) สูงกว่านโยบายเดิมอย่าง "การติดตามผู้ป่วยทุกคน (Treat All)" หรือ "การไม่ติดตามใครเลย (Treat None)" หรือไม่

## หมวดที่ 5: Explainable AI (SHAP)

### 5.1 SHAP คืออะไร?
* **SHAP (SHapley Additive exPlanations):** พัฒนามาจากทฤษฎีเกม (Game Theory) ของ Lloyd Shapley (รางวัลโนเบลเศรษฐศาสตร์)
* เปรียบเทียบตัวแปรแต่ละตัวเป็น "ผู้เล่นในทีม" และผลลัพธ์การทำนายคือ "คะแนนรวมของทีม" SHAP จะคำนวณอย่างเป็นธรรมว่าตัวแปรแต่ละตัวช่วยบวกคะแนนความเสี่ยงเพิ่มขึ้น หรือช่วยดึงความเสี่ยงลดลงเท่าใด

### 5.2 Global vs Local Explanation
* **Global Explanation (ระดับประชากร):** ดูว่าในภาพรวม ตัวแปรใดมีอิทธิพลต่อโมเดลมากที่สุด (แสดงด้วย Beeswarm Plot) เหมาะสำหรับนักระบาดวิทยาและผู้บริหารนโยบาย
* **Local Explanation (ระดับบุคคล):** ดูว่าสำหรับ "คุณตา สมชาย" ปัจจัยใดที่ทำให้ความเสี่ยงพุ่งสูงขึ้น (แสดงด้วย Waterfall Plot เช่น +ชนิดโรคเดิมเป็นความดัน, +ค่า BMI สูง, -ออกกำลังกายสม่ำเสมอ) เหมาะสำหรับพยาบาลหน้างานใช้สื่อสารกับผู้ป่วย

### 5.3 กฎเหล็ก: ข้อควรระวังในการพูดเรื่อง SHAP ต่อหน้ากรรมการ
> **"SHAP บอกได้เฉพาะสิ่งที่โมเดลใช้ในการทำนาย (Statistical Association) แต่ไม่ได้บอกความสัมพันธ์เชิงสาเหตุทางชีววิทยา (Causality)"**
* *ห้ามพูดว่า:* "SHAP พิสูจน์ว่าความดันโลหิตสูงเป็นสาเหตุทำให้เกิดโรคเบาหวาน"
* *ให้พูดว่า:* "SHAP แสดงให้เห็นว่าประวัติโรคความดันโลหิตสูงเดิม มีน้ำหนักในการผลักดันให้โมเดลทำนายความเสี่ยงเพิ่มขึ้นมากที่สุดในกลุ่มตัวอย่างนี้"

## หมวดที่ 6: บริบทหน้างาน รพ.สต. และผู้ใช้งานจริง

### 6.1 ใครคือ Primary End User?
* **พยาบาลวิชาชีพผู้จัดการโรคเรื้อรัง (NCD Care Manager)** และ **แพทย์เวชศาสตร์ครอบครัว/แพทย์ปฐมภูมิ** ประจำ รพ.สต. หรือ โรงพยาบาลชุมชน (รพช.)

### 6.2 หน้างานจริงใช้งานอย่างไร? (User Journey)
1. ผู้สูงอายุที่เป็นความดันหรือเบาหวาน 1 โรค มารับยาและตรวจสุขภาพประจำปี
2. พยาบาลกรอกข้อมูลคัดกรองทั่วไป 8–10 ข้อลงในโปรแกรม (อายุ, โรคเดิม, BMI, ความดัน, สูบบุหรี่, ดื่มสุรา, การออกกำลังกาย)
3. ระบบประมวลผลทันที และแสดงแถบสีความเสี่ยง:
   * **สีเขียว (เสี่ยงต่ำ):** นัดติดตามตามรอบปกติประจำปี
   * **สีเหลือง (เสี่ยงปานกลาง):** นัดประเมินซ้ำใน 6 เดือน พร้อมแนะนำการปรับพฤติกรรมเฉพาะจุด
   * **สีแดง (เสี่ยงสูง 15–20% แรก):** ส่งรายชื่อให้ทีมหมอครอบครัวและ อสม. ลงพื้นที่ **เยี่ยมบ้านเชิงรุก (Proactive Home Visit)** ทันที เพื่อปรับเปลี่ยนพฤติกรรมก่อนเกิดโรคที่ 2

## หมวดที่ 7: ซ้อมตอบคำถามสอบ 5 ข้อเด็ด (Defense Q&A Drill)

### Q1: "ถ้าผลออกมาแล้ว ML ชนะ Logistic Regression แค่นิดเดียว (เช่น AUC 0.75 vs 0.73) ถือว่าล้มเหลวหรือไม่?"
* **คำตอบ:** "ไม่ล้มเหลวครับ เพราะวัตถุประสงค์หนึ่งของโครงการคือการพิสูจน์ความคุ้มค่าของ ML เทียบกับ Baseline หาก ML ไม่ได้ให้คุณค่าเพิ่มอย่างมีนัยสำคัญ นั่นคือข้อค้นพบที่มีประโยชน์อย่างยิ่งต่อระบบสุขภาพไทย ว่า รพ.สต. สามารถใช้แบบประเมินคะแนนเชิงเส้นธรรมดาได้ทันที โดยไม่จำเป็นต้องลงทุนกับโครงสร้างพื้นฐาน AI ที่ซับซ้อนครับ"

### Q2: "ทำไมถึงเลือกดูเฉพาะคนที่มี 1 โรค ทำไมไม่รวมคนที่มี 0 โรคเข้ามาด้วย?"
* **คำตอบ:** "เพราะประชากรสองกลุ่มนี้มีบริบททางคลินิกและบริการต่างกันอย่างสิ้นเชิงครับ กลุ่ม 0 โรคเป็นเรื่องของ Primary Prevention ในคนทั่วไป แต่กลุ่มที่มี 1 โรค ร่างกายมีความผิดปกติทางสรีรวิทยาแล้ว และที่สำคัญที่สุดคือคนกลุ่มนี้ **มารับบริการที่คลินิก NCD ทุกเดือนอยู่แล้ว** จึงเป็นหน้าต่างโอกาส (Golden Window) ที่ระบบบริการสามารถเข้าไปแทรกแซงและป้องกันได้จริงที่สุดครับ"

### Q3: "ข้อมูล HART เป็นแบบสอบถามสัมภาษณ์ (Self-reported) จะเชื่อถือได้อย่างไรเมื่อเทียบกับผลแล็บ?"
* **คำตอบ:** "เป็นข้อจำกัดจริงของข้อมูลสำรวจครับ แต่เราป้องกันด้วยการคัดเลือกเฉพาะ **โรคที่ได้รับการวินิจฉัยโดยแพทย์ (Doctor-diagnosed)** เท่านั้น และจุดเด่นสำคัญของ HART คือมีมิติด้านพฤติกรรมและวิถีชีวิตที่เวชระเบียนโรงพยาบาลไม่มี โดยโครงการนี้วางตำแหน่งเป็น **เครื่องมือคัดกรองเบื้องต้นในชุมชน** เพื่อจัดคิวส่งตรวจยืนยันในสถานพยาบาลต่อไปครับ"

### Q4: "คุณจัดการกับคนที่เสียชีวิตระหว่างการติดตามอย่างไร?"
* **คำตอบ:** "เราจัดการด้วยวิธี **Competing Risk** ครับ โดยประเมินแบบ Cause-specific Hazard ควบคู่กับ Cumulative Incidence Function (CIF) เพื่อไม่ให้เกิดอคติจากการตัดผู้เสียชีวิตทิ้งหรือนับผู้เสียชีวิตเป็นผู้ไม่เกิดโรคครับ"

### Q5: "ถ้าเปิดไฟล์ HART จริงแล้วพบว่ามีจำนวน Event น้อยเกินไป จะทำอย่างไร?"
* **คำตอบ:** "เราได้เตรียม **Plan B (Dual-Dataset Strategy)** ไว้แล้วครับ โดยจะใช้ฐานข้อมูลระยะยาวสากลที่เป็น Sister Study เช่น ELSA (อังกฤษ) หรือ HRS (สหรัฐฯ) ในการพัฒนาและจูนโมเดล แล้วนำตัวแปรที่ Harmonize แล้วมาทำ **External Validation บนฐานข้อมูล HART ของไทย** ซึ่งจะยิ่งเพิ่มความน่าเชื่อถือทางวิชาการในระดับนานาชาติครับ"
